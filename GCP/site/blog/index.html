1) Building the frontend first (on purpose)

I started this project by treating the frontend as a finished product — not a placeholder.

The site is intentionally static. HTML, CSS, and a small amount of JavaScript. No frameworks, no build step, no client-side complexity hiding the real work.

This forced clarity early:

  • What data actually needs to exist?
  • What should be static vs dynamic?
  • What contracts does the backend need to satisfy?

By wiring the visitor counter placeholder into the UI before the backend existed, I locked in the API shape early. That eliminated guesswork later.

Frontend-first wasn’t about visuals. It was about defining interfaces, constraints, and expectations — the same way I approach real systems.

2) Moving to Cloudflare: DNS, HTTPS, and reality

Static hosting is easy. Owning your domain, HTTPS, and routing is not.

Cloudflare sits between users and Google Cloud Storage. That sounds simple until you actually deal with:

  • apex vs www redirects
  • directory-style URLs like /blog/
  • caching behavior masking deployment mistakes

I deliberately chose Cloudflare to control cost and avoid always-on GCP load balancers. That decision came with tradeoffs — especially around redirects.

Fixing /blog vs /blog/index.html forced me to understand how Cloudflare evaluates rules, ordering, and redirect loops.

This wasn’t about “making it work.” It was about understanding the edge well enough to debug it without guessing.

3) The visitor counter: small feature, real backend decisions

A visitor counter sounds trivial — until you build it properly.

I implemented the backend using Cloud Run and Firestore, provisioned via Terraform and deployed as a container.

The design was intentional:

  • Browser calls an API, not the database
  • Firestore access scoped via a service account
  • CORS locked to my domain
  • Scale-to-zero to avoid idle cost

Most of the effort wasn’t writing Python. It was aligning IAM, container images, regions, and environment variables so everything behaved predictably.

This is where Infrastructure as Code mattered most. Every fix became a commit. Every change was reversible. No mystery state.

The result is intentionally boring — and that’s the point.
